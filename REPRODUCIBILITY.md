# Reproduction guide

The project intentionally keeps its **theoretical mechanisms**, **open-ended LLM output**, and **measurement logic** separate. This separation matters because the predictions of the analytical model are not treated as if they were generated by an AI researcher.

## Two different run paths

### A. Stylized theory harness

```bash
python scripts/run_demo.py
```

This writes `summary.json`, `projects.csv`, `traces.jsonl`, and `run_metadata.json` under `sample_results/` (only compact engineering summaries are tracked). The deterministic mock backend is a plumbing fixture, **not evidence about AI-enabled science**.

### B. Live open-weight benchmark

```bash
pip install -r requirements.txt
python scripts/run_stage1_benchmark.py \
  --model YOUR_MODEL_ID \
  --model-label model-label \
  --conditions-file configs/stage1_conditions.yaml \
  --n-seeds 2 --n-agents 3 \
  --out live_runs/my_run
```

Start a local server exposing an OpenAI-compatible `/v1/chat/completions` endpoint first; set `SUA_BASE_URL` or use `--base-url`. The benchmark writes `raw_traces.jsonl` and `manifest.json`.

`raw_traces.jsonl` contains the actual prompt, raw response, parsed record, seed, condition, model label, and code commit. New experiment conditions live in editable YAML, enabling other scholars to alter evaluation rules without modifying the generation script.

## Historical frozen Stage-1 pilot

The October 22, 2026 pilot was run against commit `da51fe69e6ddaacbd7f8cde57216d718c552e231` (Actions run `39708296202`). It crossed two model families, three institutional conditions, two seeds, and three agents per cell. The recorded total is 36 attempted trajectories and 34 parsable structured records.

The original `benchmark_summary.json` and its manuscript-reported descriptive statistics are immutable historical outputs. Later changes to code or analysis **must not overwrite those numbers**. Extended analyses—including candidate-versus-selected idea overlap—should be labeled exploratory V2 reanalysis and kept in separate files.

The run artifacts in GitHub Actions have retention limits, so the submission snapshot is also part of the reproducibility record; do not assume GitHub's temporary artifact URLs will remain valid indefinitely.

## Critical measurement distinctions

- The prompt assigns every agent a total **100-point** verification budget. Therefore average points per selected project is `100/n` by construction. Do not interpret it as independently observed verification effort or quality.
- The original parsing criterion is permissive. An output counted as structurally usable may still violate parts of the experimental instructions (e.g., selecting more than two projects under a best-two rule). Any protocol-compliance analysis should report those violations separately.
- Lexical/Jaccard overlap is a useful diagnostic, not a validity-tested measure of idea similarity or scientific novelty.
- The numeric `ai_capability` in the stylized theory harness is not a language-model capability treatment. Live semantic treatments must be made through actual model/corpus changes, not by telling the model it is in a "high-AI" regime.
- Institutional prompts necessarily communicate evaluation and priority rules; prompt-sensitivity checks are required before strong behavioral interpretations.

## Building from the frozen data

For each model's raw-trace JSONL from the snapshot:

```bash
python scripts/analyze_stage1_benchmark.py \
  live_runs/qwen/raw_traces.jsonl \
  live_runs/smollm/raw_traces.jsonl \
  --out live_runs/combined
```

The latest analyzer additionally reports candidate-idea and selected-idea overlap, responding to the revised proposal's competing explanation about evaluation breadth and conservative idea selection.

This is a **theory-building and boundary-testing** instrument; it does not establish a calibrated causal effect on human research behavior.
